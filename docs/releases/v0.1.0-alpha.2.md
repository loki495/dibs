# Dibs v0.1.0-alpha.2

<!-- Draft GitHub release body: copy everything below this line into the release description for tag v0.1.0-alpha.2 (mark it as a pre-release). -->

**This is an alpha.** Schemas, MCP tool arguments and defaults can still change between alpha releases. Back up `database/database.sqlite` before every upgrade.

Two security fixes on top of [v0.1.0-alpha.1](v0.1.0-alpha.1.md), plus a safety guard for the test suite.

## Agents only see trusted authors' text

Anyone who can open an issue or comment on the mirror repository could write instructions that an agent would then read and act on, with its own (much wider) permissions.

- Dibs still imports everything from GitHub, and the web UI still shows everything.
- Every agent-facing read (all MCP tools and the `todo:agent:*` CLI) replaces the title, body, search excerpt, comment or closing note written by an untrusted author with a short note, and marks it `withheld: true`. Ids, state, labels and the author's login stay visible.
- **Trusted** means the mirrored repository's owner plus the logins in the new `DIBS_TRUSTED_GITHUB_AUTHORS` (comma-separated, empty by default). Text created through Dibs itself has no GitHub author and is always shown, so local-only instances see no change.
- Text imported from deleted GitHub accounts (`ghost`) is withheld.

See [Prompt injection through imported GitHub content](../security-model.md#prompt-injection-through-imported-github-content) in the security model.

## Demo: a cap on per-visitor database copies

Every demo request without the visitor cookie copies the template database, so a client that never sends the cookie back could fill the disk. The demo now keeps at most `DEMO_MAX_INSTANCES` copies (default 2000) and evicts the least recently written first. Only affects deployments with `DIBS_DEMO_MODE=true`.

## Tests refuse to run against a real database

The suite now aborts before touching any database unless the connection is in-memory SQLite, so a cached config or an exported `DB_DATABASE`/`DB_URL` can no longer point it at real data.

## Dependencies

Dropped the unused `concurrently` dev dependency and updated `source-map-js`, clearing two Dependabot advisories in build-time tooling. Neither reached the built app.

## Upgrade notes for existing installs

Back up first (see [Backup, restore and upgrade](../../README.md#backup-restore-and-upgrade)).

- **Run migrations.** One additive migration (`issues.author_login`). `bash docker/setup.sh` runs it, or `docker compose exec -T -u www-data app php artisan migrate --force`.
- **If you mirror GitHub, run an import once afterwards:** `docker compose exec -T -u www-data app php artisan todo:sync`. That fills in issue authors. Until then, existing imported issues read as created through Dibs, so they are shown to agents.
- **If your GitHub token's account isn't the repository owner, add its login to `DIBS_TRUSTED_GITHUB_AUTHORS`.** Otherwise your own text, once it round-trips through GitHub, is withheld from agents. Add anyone else whose text agents should read.
- **CLI output change:** `todo:agent:show`, `todo:agent:create` and `todo:agent:update` now print the same JSON shape as the `todo_show` MCP tool (with up to 50 comments) instead of the web UI's. Update any scripts that parse it.
- **Reconnect agent sessions** after upgrading, so their MCP server loads the new code.

## Known limitations

Unchanged from alpha.1: see [Known limitations](../../README.md#known-limitations). Withheld issues still show their labels, state and author login to agents.
