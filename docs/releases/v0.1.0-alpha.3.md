# Dibs v0.1.0-alpha.3

**This is an alpha.** Schemas, MCP tool arguments and defaults can still change between alpha releases. Back up `database/database.sqlite` before every upgrade.

Richer `todo_revise`, local ids in the web UI, JSON workspace export/import, and a guard that stops a GitHub pull from overwriting unpushed edits. Follows [v0.1.0-alpha.2](v0.1.0-alpha.2.md).

## `todo_revise` and `todo:agent:update` change labels, Group and parent

- **Labels:** `addLabels` / `removeLabels` (names, at most 20 each) are deltas, so labels the caller never saw are left alone. Names match case-insensitively and are stored lowercase, a missing added label is created, and removing a label the task lacks is ignored. A blank name, or one name in both lists, is a handled error. Knowledge labels work too; adding one moves the task to Knowledge. CLI: repeatable `--add-label` / `--remove-label`.
- **Group:** `groupId`, `newGroupName` (reuses or creates the Group of that name in the task's area) or `clearGroup`, at most one of the three. CLI: `--new-group`, `--clear-group`.
- **Parent:** `parentId` moves the task under another (cycle- and self-parent-checked); `clearParent` detaches it. They cannot be combined. CLI: `--parent`, `--clear-parent`.
- A blank Group name, an unavailable parent, or a Group change on a task with no area is a handled error that changes nothing.

Details in the [agent interface](../agent-interface.md).

## Local id shown in the web UI

The id agents use is the local database id, but the UI showed only the GitHub number, so an id quoted by an agent could find an unrelated task in the search box. List rows, the detail header and deleted rows now show "id N", and a numeric search matches the local id as well as the GitHub number. `todo_search` is still text-only.

## JSON workspace export and import

**Settings, Data export/import** downloads workspace content and history as JSON. Import validates and previews an archive, then restores it in one transaction into an empty workspace only; existing records are never overwritten or merged. Accounts, credentials, claims and runtime queues are not exported. See [workspace transfer](../workspace-transfer.md).

## A pull refuses while pushes are pending

Pushing is last-local-write-wins, and a pull replaces local text with GitHub's, so a pending local edit used to be lost. `todo:sync` and the web pull now stop before fetching, with an error, while the push queue has any pending, failed or needs-attention row. Drain the queue or resolve those rows, then pull.

## Documentation

- The README documents Codex and Antigravity MCP setup alongside Claude Code and opencode.
- Several docs claimed GitHub pushes check for conflicts. They don't: a remote edit made since the last pull is overwritten. The docs now say so.

## Upgrade notes

Back up first (see [Backup, restore and upgrade](../../README.md#backup-restore-and-upgrade)). No new migrations. Reconnect agent sessions after upgrading, so their MCP server loads the new tool arguments.
